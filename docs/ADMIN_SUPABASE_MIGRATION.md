# Admin trên Supabase: bản chuẩn bị cục bộ

Migration `supabase/migrations/20261110170000_admin_rls_foundation.sql` chỉ mới được áp trên **Supabase cục bộ**. Database thật hiện ở Alembic revision `20261110_22`; chưa có migration Admin trên đó. `NEXT_PUBLIC_SUPABASE_ADMIN_ENABLED=false` trong `apps/admin/.env.example`, nên Admin đang chạy bằng FastAPI như trước.

Migration tạo `englify_is_admin()` kiểm tra `admin_members` bằng `auth.uid()`. Các bảng biên tập có chính sách RLS riêng cho admin; tài khoản thường chỉ đọc nội dung đã phát hành qua chính sách cũ và không thể ghi. Bảng `quiz_options`/`quiz_answer_keys` vẫn riêng tư với người học. Trigger ghi audit cho thao tác từ JWT admin, chặn phát hành quiz thiếu đáp án, chặn sửa câu hỏi đã có lượt làm và chặn sửa đáp án khi câu hỏi đang phát hành. Tài khoản FastAPI dùng kết nối DB không có `auth.uid()` vẫn dùng cơ chế audit hiện tại.

Trang Admin có adapter Supabase dưới cờ cấu hình, hỗ trợ login hiện có, schema form, danh mục, tìm kiếm, phân trang, tạo/sửa, draft/publish, lưu trữ, analytics và audit. Khi cờ tắt, mọi request vẫn đi FastAPI. Bản Supabase dùng PostgREST/RLS và RPC metrics; **chưa chuyển cờ trên dự án thật**. Việc ghi bản ghi quiz và đáp án hoặc badge và quy tắc là hai request riêng; nếu request thứ hai lỗi, bản nháp đầu tiên có thể còn lại để admin sửa. Cần kiểm thử giao diện và bổ sung thao tác nguyên tử trước khi coi là tương đương hoàn toàn.

Kiểm thử cục bộ đã chạy: reset database từ trống; hai tài khoản Auth tạm; user thường bị chặn ghi và xem audit/đáp án; admin tạo draft từ điển, phát hành để học viên đọc, tạo quiz draft, bị chặn phát hành thiếu lựa chọn, được phát hành sau khi đủ lựa chọn, không thể sửa đáp án đang phát hành hoặc bài đã có lượt làm. Audit ghi create/publish. Script xóa tài khoản và nội dung tạm rồi chạy lại được. Adapter có 3 unit tests; `npm.cmd run check` đạt 92 Vitest tests, TypeScript/lint/build. Backend integration trên DB cục bộ đạt 48/48. Chưa kiểm tra trình duyệt Admin hoặc deploy migration này.

Để thử Admin trên Supabase local sau khi reset migration, đặt `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321` và **anon/public key cục bộ** vào `apps/admin/.env.local`; chỉ môi trường development chấp nhận loopback. Đặt `NEXT_PUBLIC_SUPABASE_ADMIN_ENABLED=true` tại máy thử. Tạo tài khoản test qua Auth cục bộ, cấp `admin_members` cho đúng tài khoản trong DB local, rồi kiểm tra hai phiên admin và learner trên trình duyệt. Không dùng service role key trong `.env.local`.

Sau khi có quyết định chuyển Admin: áp migration lên môi trường thử riêng, chạy kiểm thử CRUD toàn bộ resource và audit khi có lỗi, thử trình duyệt với hai tài khoản; sau đó mới áp lên production và bật `NEXT_PUBLIC_SUPABASE_ADMIN_ENABLED=true`. Không chia sẻ hoặc cấp service role key cho trình duyệt.
